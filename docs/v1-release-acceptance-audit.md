18 October 2026. Application source `dd36b0dab568684d6c8ee6c66d47e27a76b9fca4`;
full backend source `257b2733e5f7f61e2d3d9ed971a55a5f7a96fd94`; audit base
`3082f1aa2f579b622bb09ae1fc3e238e20818e1f`. Ownership contract

The entire `go-live-plan.md`, current execution status, wave-4 validation, source,

change product scope, product source, migrations or the shared plan.

**V1 is not release-ready.** No aggregate green score is assigned. The 58-row
[machine-readable matrix](../artifacts/v1/release-audit/acceptance-matrix.json)

Every row carries exact hashed source/test/artifact references, observed evidence,
remaining work and ownership. A source implementation or passing unit test is not
full product acceptance. All rows retain a final-candidate acceptance gate.

## Findings that affect acceptance

1. **V03: Instagram retrieval and CSV are implementation gaps.**
   `services/imports_v1.py:collect_claim` explicitly needs an injected owned-media
   adapter and otherwise fails `provider_capability_pending`. The production
   `workers/v1_imports.py:_drain` passes no adapter. `ImportJobCreate` accepts
   website/Instagram/uploaded-media and `UploadCreate` only JPEG/PNG/MP4: the native
   CSV fallback is absent. Synthetic adapter/media fixtures cannot satisfy these
   requirements. Website JSON-LD, uploaded bytes and review/recovery are implemented.
2. **V08: current-SKU automated answers remain incomplete.**
   `test_channel_operator_db.py:test_activated_catalogue_handoffs_before_legacy_fact_reply`
   and `test_whatsapp_activated_context_handoffs_without_frozen_price_or_stock`
   intentionally prove human handoff for activated catalogue products. This is a
   sound safety boundary, but does not satisfy catalogue-aware automated answers
   using authoritative current SKU options, price and availability. Real delivery
   remains an additional gate after implementation.
3. **V12: SSR SEO is partial.** Product/category SSR, configured canonicals, metadata
   and JSON-LD exist. No supported legacy URL inventory/redirect implementation or
   sitemap acceptance was found. Migration reconciliation and domain-owner
   routing authority remain required; third-party subdomains may require their
   provider's action. Existing private order links also need migration proof.
4. **V13 is conditional, not waived.** The audited checkout imports IN-only
   `AddressInput` with six-digit Indian postcode and enforces INR. If Dharaa moves,
   its actual destination/address/shipping/charge/payment/display requirements
   must pass first. Otherwise preserve its existing international route or defer
   that seller's migration. There is no worldwide purchasing claim.
5. **Local-team work stays visible.** Explicit expiring support grants/global sales
   access, analytics and verified customer identity links remain owned by the local
   team and in progress, rather than being simulated by membership assignments.
   The current assistance board is useful scoped functionality, not support access
   or complete sales-assisted onboarding. `onboarding_complete` remains false.
6. **Operational/product gates remain open.** Actual Meta/Razorpay/private ParcelDesk
   canaries, approved real import/media, physical phones, the full integrated
   onboarding/acceptance matrix, the agreed pilot traffic/performance envelope,
   operational alerts/usage/support runbooks, actual restore/application rollback,
   new locked-image builds and hosted CI/multiarch results are not established by
   the historical local tests. Current-provider approval is not inferred from saved
   credentials or historical account documentation.

## Dispositions

- `source_implemented`: audited source exists; source alone proves no product outcome.
- `actual_migrated_native_verified`: saved actual migrated/native evidence was checked;
  the audit did not rerun it.
- `simulated_provider`: a provider input, camera or delivery transport was synthetic.
- `live_provider_physical_device_pending`: authorized real integration/device proof remains.
- `not_implemented`: required implementation is absent from the audited candidate.
- `local_team_owned_in_progress`: explicit local product ownership, without completion credit.

Rows can contain several dispositions because partial implementation, synthetic
provider checks and missing real acceptance coexist. No disposition silently
narrows a completion criterion.
