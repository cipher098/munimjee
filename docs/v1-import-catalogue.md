# Reviewed source facts to private canonical drafts

This slice connects durable import candidates to the existing canonical catalogue
writer. It creates a private inactive Product with reviewed SKUs; activation,
store publication, checkout policy and reservation stay separate explicit actions.
It does not fetch sources or make provider calls.

The default-off `V1_IMPORT_BRIDGE_ENABLED` setting controls creation. Native
mutation/session/CSRF checks and current `catalogue.write` authority precede
creation or replay. The session and committed membership/user/Business/Seller
state are checked again after allocation locks. Reads require `catalogue.read`.
See [concrete contracts](contracts/import-catalogue/README.md).

Business → Storefront → source candidate locks serialize review and first creation.
Source candidate reads use scalar projections, avoiding retained ORM document
state. In one caller-owned transaction the bridge validates current facts and
exact allocation, explicitly approves a pending/review candidate if required,
uses the existing reviewed-product writer, records the approved source snapshot
and exact allocation/reviewer, and appends the import audit. Failure rolls all of
these changes back. The bridge never commits its caller's transaction.

A source can create one canonical product. Receipt keys are tenant scoped;
exact retries return the original product even after reimport. Conflicting keys
or another creation request for that candidate return409. Reimport changes stay
proposals for review; they cannot overwrite existing catalogue stock or facts.
The internal catalogue creation key is generated by the server and recorded in
the immutable receipt; it is not a browser-controlled namespace.

Unknown stock/options remain unknown and block creation. All confirmed option
combinations (maximum500) require explicit integer stock allocation summing to
the confirmed source total. INR prices convert exactly to integer minor units;
other currencies, unsupported dimensions and out-of-range totals fail visibly.
No product-page URL, private upload or extracted evidence becomes a public photo;
optional photos must be explicitly supplied with seller review.

`0047_v1_import_catalogue_bridge` follows actual0046 and creates immutable receipt
snapshots with composite tenant foreign keys for candidate, product and reviewer
membership. Database tests use the P01 guarded import_bridge_w3 lane and real
Alembic migrations, never create_all. Evidence is under
`artifacts/v1/import-catalogue/`. The focused gate covers atomic rollback,
concurrent exact retries, stale revisions, reimport, unknown facts, allocation,
role/tenant/revocation negatives, native CSRF, bounded malformed JSON, and native
session revocation during an actual PostgreSQL lock wait. A complete real browser
import-workspace journey remains pending remote UI integration; these API checks
do not claim that product gate or source-provider approval.
